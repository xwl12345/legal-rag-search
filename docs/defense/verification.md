### 2.2 OCR 诊断路径（通过 ✅）

构造无文本层的伪扫描 PDF（`test/data/fake_scanned.pdf`，仅含图形操作）后导入：

- 文本层提取为空 → 自动进入 OCR 回退 → 检测不到可用 Python/PyMuPDF 环境 → 弹出「文档导入提示」诊断框：
  > ⚠️ 未导入任何文档：1 个文件未能提取可检索文本
  > 失败原因：fake_scanned.pdf：未找到可运行 PyMuPDF（fitz）的 Python 解释器，请安装或配置 Python 环境

  截图：07-ocr-diagnostic-dialog.png。失败原因精确、不静默吞错，符合设计。
- 已录入应用状态栏的导入计数（21 篇 / 118 块 / OCR 失败诊断）均有 UI 文本为证。

### 2.3 异常记录（一次偶发，未再现 ⚠️）

首个长会话 GUI 实例中，在「导入 21 篇 → 筛选切换 → 聚合搜索 → 导入 test.pdf → 导入 OCR 失败 PDF」之后，出现所有检索返回 0 条的异常；重启应用并完整重放同一操作序列（含 OCR 失败导入、聚合搜索、二次聚焦搜索）**无法复现**，全部正常（20 条 → 5 条 → 20 条）。

处置：
1. 新增回归测试 `test_e2e_failed_ocr_import_then_search`（核心层复现「OCR 失败导入 → 再检索」场景），**通过**，证明检索引擎核心逻辑在该场景下无恙；
2. 判定为 GUI 层偶发异常（疑似长会话下的前端状态问题），记录在案；如再次出现，可按「清空索引 / 重启应用」恢复；
3. 答辩演示建议使用全新启动的应用实例，演示顺序：导入 → 检索 → 筛选 → 聚合（与本次验证的正常路径一致）。
